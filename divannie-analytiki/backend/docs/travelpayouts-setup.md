# Какой Travelpayouts API подключаем первым

Актуальное состояние 0.3.0: [полная поставка Backend/Data](data-delivery.md). Более ранние ограничения ниже относятся к соответствующим этапам; текущие endpoints и блокеры перечислены в итоговом отчёте.
Первый кандидат для подключения — **Aviasales / Flight Data Access API**, то есть данные о найденных авиабилетах из кэша. Это источник для исследования направлений и оценок цен. Он не подтверждает живое наличие/тариф для состава гостей и не заменяет отельный API.

## Где открыть

Официальная документация ссылается на [API программы Aviasales](https://www.travelpayouts.com/programs/100/tools/api). Откройте её в браузере с авторизацией Travelpayouts. Если интерфейс изменился и ссылка перенаправляет, в [справочном центре](https://support.travelpayouts.com/hc/en-us/categories/200358578) ищите **Flight Data Access API**, **API данных авиабилетов** или **Aviasales Data API**. Текущий авторизованный интерфейс в этой среде не проверен, поэтому точное расположение меню не утверждаем.

На присланном скриншоте:

- «API ссылок» — автоматизация партнёрских ссылок.
- «Данные API» по описанию карточки — сделки/клики/бронирования партнёрских инструментов; само это название не означает API цен авиабилетов.
- «Файлы данных» — выгрузки/каталоги.

Эти карточки не являются основанием выбирать API поиска рейсов. Нужна документация именно Flight Data Access API.

## Что удалось проверить

Прочитаны официальные исходники документации организации Travelpayouts:

- [Введение, авторизация и кэш](https://github.com/travelpayouts/slate/blob/master/source/index.html.md).
- [Flight Data Access API v1](https://github.com/travelpayouts/slate/blob/master/source/includes/_dataapiv1.md).
- [Flights Search API и требования доступа](https://github.com/travelpayouts/slate/blob/master/source/includes/_searchapi.md).

Введение явно сообщает, что Data API возвращает данные из кэша. В документации указана авторизация через `X-Access-Token` или параметр token. Для будущего клиента предпочитаем header, чтобы credential не попадал в URL. В v1 описан endpoint `https://api.travelpayouts.com/v1/prices/cheap`. После настройки секрета endpoint проверен реальным read-only запросом: status=ok, один подходящий cached estimate. Подтверждён доступ к Data API; доступ к Search API/бронированию этим не подтверждён. Подробности — в отчёте data-delivery.md.

Search API описан отдельно: доступ по заявке, server-side запросы и условия использования. Наличие Data API token не доказывает доступ к Search API. Не подделывайте IP/host или требования приложения ради подключения. Перед использованием сверить актуальные условия с поддержкой.

Прямой доступ к support.travelpayouts.com из текущей среды вернул 403 CONNECT; исходники документации на raw.githubusercontent.com удалось прочитать. Они могут отставать от кабинета — ссылки на меню рассматриваются как указатели, не проверенное состояние UI.

## Действия владельца аккаунта

1. Открыть раздел API Aviasales и проверить доступ к Flight Data Access API.
2. Token не отправлять в чат и не коммитить. Способ безопасной привязки настроить после добавления соответствующего клиента; текущий mock-сервис token не использует.
3. Для live-поиска отдельно проверить требования и подать заявку на Search API, если это нужно демо. Это не блокирует разработку mock/data-контрактов.
4. Доступ к отелям подтвердить отдельной документацией продукта: API авиаданных его не обеспечивает.

## Реализованный адаптер и дальнейшие границы

Адаптер **исследовательских авиаданных** уже реализован с собственным контрактом cached estimate и проверен реальным запросом. Нельзя автоматически превратить минимальную cached-цену в `Bundle` с подтверждённой стоимостью всей поездки: нужны точные параметры пассажиров/дат, оба направления, источник и сроки действия. Contract tests выполнены на синтетических ответах через HTTP MockTransport; после безопасной настройки ключа выполнен также успешный реальный запрос. Готовность полного live-бандла по-прежнему не заявляется.
