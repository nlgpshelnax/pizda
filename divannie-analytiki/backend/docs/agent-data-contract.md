# БД, синхронизация и поиск тура

Схема SQLite: [`catalog.sql`](../backend/src/trip_data/sql/catalog.sql). Она нормализована: отель и зависящий от дат/гостей тариф хранятся отдельно, чтобы не приписывать одну цену всем поездкам. При запуске `CatalogDB` также применяет добавочные колонки и миграции (см. `database.py`). Пользуйтесь схемой через приложение, а не создавайте вторую БД с несовместимыми таблицами.

| Из задания | Фактические таблицы/представления |
|---|---|
| hotels | `hotels`, `hotel_quotes`, представление `agent_hotels` (цена в копейках за всё проживание) |
| transport | `transport_quotes`, представление `transport`; отдельные `transport_estimates` не являются бронируемыми |
| weather | `weather`, дата и срок действия прогноза; месячный климатический агрегат пока не реализован |
| guest_rules | `guests`, `hotel_quotes`, представление `guest_rules` содержит условия конкретной котировки |
| dates_calendar | `calendar_dates`, представление `dates_calendar`; цена поездки не глобальное свойство календарной даты |
| budget_benchmarks | `budget_statistics`, представление `budget_benchmarks`; раздельно по городу, месяцу, гостям, ночам и режиму данных |
| visa_rules | `visa_rules`; неподтверждённые правила имеют статус `unknown` |
| activities | `activities`, представление `city_vibes` считает активные POI |

Есть индексы по городу/звёздам, питомцам/датам тарифа, типу/датам и маршруту транспорта, погоде и активностям. Время хранится с offset и timezone, неизвестные значения — NULL. Не заданные отелем check-in/check-out не считаются подтверждёнными 14:00/12:00. Профиль паспорта использует ISO-2 (`RU`), а не ISO-3 (`RUS`).

`budget_statistics` вычисляет p25/медиану/p75 линейной интерполяцией по отсортированным ценам, с округлением до копейки. Это статистика **цен проживания за весь срок и всех гостей** по доступной выборке, не общая стоимость поездки; размер выборки и режим данных сохранены. Авиа/ЖД бенчмарки и месячный климат требуют отдельных достаточно полных источников и пока не рассчитаны.

## Синхронизация

```bash
uv run python scripts/sync_service.py --once --offline
uv run python scripts/sync_service.py --once
uv run python scripts/sync_service.py --interval 1800
```

Сервис использует существующий ingestion worker: atomic UPSERT, хеши, блокировка параллельной загрузки, ограничение времени вызовов, кэш, журнал статуса, пересчёт бюджетных групп. Offline загружает локальные fixtures; они помечены `mock`. При сбое онлайн-источника worker сообщает `partial` и сохраняет ранее загруженные данные; `--once` возвращает ненулевой код, чтобы сбой был заметен. API каталога при этом читает локальные данные. Включение mock не означает подтверждения наличия или цены.

Подключены Open-Meteo, OSRM и Travelpayouts Data API. Разовые ограниченные снимки OSM загружаются через `scripts/load_database.py --refresh-hotels`; Overpass может быть недоступен. LiteAPI-клиент существует, но автоматический импорт реальных тарифов пока не подключён. Контракты/доступы Viajante, rzd-api, Passport Index и Travelpayouts MCP не подтверждены; загрузчиков для них здесь нет. Вместо выдуманных ответов остаются `unknown`, пустые наборы или явно помеченные демоданные. Публичные API имеют лимиты и условия, их необходимо согласовать до полного импорта.

## Запрос агента

`POST /api/v1/tours/search` принимает `{"request": <TripRequest>, "plan_version": 1, "passport_country": "RU"}`. Пример `TripRequest`: внутреннее поле `request` из `data/fixtures/search-request.json`. Оно включает origin, destination, даты, гостей, бюджет и потребность в питомцах. Ответ содержит `search.options`, `search.rejected` с кодами причин, прогноз по датам из БД, предварительную визовую запись и статус проверки стыковок. Бандлы собираются из записей БД и проходят валидатор стыковок, бюджета, вместимости, животных и сроков котировок. Сохранённый комплект — только mock; проверка визы обязательна, бронирование не выполняется. Прогноз может быть пустым или покрывать лишь часть дат.

Рабочий пример и детали ограничений: [архитектура наполнения](database-first.md), [инструкция роли 1](role-1-ai.md), [`/docs`](http://127.0.0.1:8000/docs) после запуска backend.
