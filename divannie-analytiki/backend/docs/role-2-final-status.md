# Backend/Data: автоматизация и оставшиеся внешние доступы

**Текущий источник исследований отелей — [Xotelo](xotelo.md)**. LiteAPI ниже оставлен как история альтернативной интеграции; банковская карта для Xotelo не нужна. Оценки привязаны к датам и взрослым, исключаются после TTL и не являются ценой подтверждённого тура. Запускайте `uv run python scripts/sync_xotelo.py --interval 21600` отдельным процессом для регулярного обновления. Совместный прогон с агентом/UI и подключение подтверждённых источников ЖД, отелей, виз и трансферов остаются открытыми.

Выполнены: общая БД/миграции, реальные OSM карточки/POI, live-погода/маршруты/авиаоценки, контракты и проверки бандлов, кэш/snapshots, сохранённые планы/CAS, демозаказы/услуги, загрузчик, worker по расписанию, data-quality проверки, импорт проверенных котировок и альтернативный клиент гостиничных тарифов.

Это не полное live-бронирование: гостиничные тарифы требуют доступа к поставщику, данные ЖД/виз/оплачиваемых трансферов пока не подтверждены; UI/чат интегрируются владельцами других ролей.

## Автоматическое обновление

Из корня репозитория, с безопасно настроенными credentials:

```bash
export UV_CACHE_DIR="$PWD/.runtime/uv-cache"
uv run python scripts/ingestion_worker.py --once
uv run python scripts/check_data.py
# Длительный foreground-процесс, остановка Ctrl+C:
uv run python scripts/ingestion_worker.py --interval 1800
```

Worker раз в 30 минут обновляет API-источники; TTL предотвращает лишние обращения. OSM не скачивается каждые 30 минут: его bounded refresh запускается отдельно и реже. OS file lock защищает от параллельных worker, включая отдельные процессы. Результаты сохраняются в ingestion_jobs, source-level записи — в ingest_runs. Ошибки не стирают предыдущие записи. `--offline --once` проверяет локальные импорты без сети. `--once` возвращает ненулевой exit code при partial/failed.

Длительный worker требует постоянно работающей машины/контейнера. Временная cloud-задача может остановиться; после восстановления snapshot worker запускается заново. Секреты передаёт окружение/secret manager. Никаких ключей в crontab, аргументах или Git. Windows locking предусмотрен, но в текущей среде проверены Linux-процессы.

`GET /api/v1/catalog-quality` и check_data показывают целостность, FK, просроченные данные, последние ошибки источников и отсутствие реальных тарифов. ok означает отсутствие integrity errors; warnings, включая NO_REAL_HOTEL_RATES, не означают готовность реального бронирования.

## Альтернатива API Островка: LiteAPI/Nuitee

Изучена официальная v3-документация:

- https://docs.liteapi.travel/reference/get_data-hotels
- https://docs.liteapi.travel/reference/post_hotels-rates
- https://liteapi.travel/ — сайт предлагает sandbox без банковской карты; условия аккаунта нужно подтвердить при регистрации.

Реализованы:

- `POST /api/v1/hotels/provider-search`: city, country, limit → собственные ID LiteAPI.
- `POST /api/v1/hotels/rates`: hotel_ids, check_in/check_out, guests, guest_nationality → тарифы на один номер/состав гостей.

Нельзя передавать OSM ID вместо LiteAPI ID или сопоставлять объекты только по похожему названию. В запросе явно передаются гражданство и возраста детей. Ответы sandbox подписаны sandbox. Цены не масштабируются на другие даты/гостей; неподходящий occupancy исключается. Налоги/питомцы/отмена требуют проверки, поэтому mandatory_fees_known=false, requires_recheck=true и bookable=false. Никаких prebook/payment операций нет.

Настройки: TRIP_LITEAPI_KEY (SecretStr), TRIP_LITEAPI_ENVIRONMENT=sandbox по умолчанию. Ключ только в request-scoped X-API-Key для api.liteapi.travel. В настройках среды подготовлен необязательный персональный секрет LITEAPI_KEY → TRIP_LITEAPI_KEY. Без ключа endpoints возвращают not_configured. Реальный запрос LiteAPI **не выполнен**: ключ отсутствует. HTTP-контракт проверен синтетическими ответами; это не live-проверка доступа/наличия.

## Импорт проверенной выгрузки

```bash
uv run python scripts/import_hotel_rates.py /path/to/reviewed-rates.json
```

Файл — JSON array HotelQuote из docs/components.schema.json: реальный property_id из нашей БД, точный scope, вся стоимость проживания для указанного состава гостей, условия и provenance.kind=snapshot с HTTPS source_url, fetched_at/valid_until. Импортёр не проверяет веб-страницу автоматически: подтверждение фактов выполняется до импорта. Рекламное «от …» не подходит для точной котировки.

Импорт атомарный, повтор по тому же содержимому — skipped. Неизвестный/mocked hotel_id или другой город отклоняются. При ошибке прежние котировки сохраняются. Импорт не включает гостиничный тариф в live checkout автоматически: нужен отдельный полный реальный бандл и перепроверка ограничений. Просроченные снимки сохраняются для анализа, но должны исключаться из текущего подбора.

## Внешние prerequisites, которые код не заменяет

1. Ключ LiteAPI или другого выбранного поставщика тарифов; production-доступ отдельно от sandbox.
2. Реальный источник цены/вместимости/детских кресел/питомцев для трансфера: OSRM даёт только дорогу.
3. Официальный/партнёрский ЖД и актуальные визовые правила; сейчас соответствующие статусы честно unknown/not_configured.
4. Реальный UI/chat integration с ролями 1/3 и общий eval роли 4. Data-evals не оценивают качество LLM.
