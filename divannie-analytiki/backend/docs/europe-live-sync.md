# Реальные источники: синхронизация Европы

Запускать из корня репозитория с Python 3.12 и uv:

```bash
uv sync --frozen
uv run python scripts/sync_live_data.py --once
# Долгоживущий процесс: повторное обновление через 7200 секунд после завершения цикла
uv run python scripts/sync_live_data.py
# После ручного прогона можно отложить первый запуск на два часа:
uv run python scripts/sync_live_data.py --wait-first
# Проверить только выбранные направления:
uv run python scripts/sync_live_data.py --once --city Белград --city Будва --city Париж
```

Рабочая реализация — `backend/scripts/sync_live_data.py`, короткая обёртка — `scripts/sync_live_data.py`. `--wait-first` переносит первый запуск на один интервал; `--interval` допускает минимум 3600 секунд, `--weather-only` обновляет только текущую погоду, `--limit N` ограничивает начальный набор. Два синхронизатора этого типа не работают одновременно: используется lock. Процесс нужно поддерживать работающим через системный менеджер; он не устанавливается автоматически. HTTP-вызовы и ошибки записываются в журнал процесса, результаты источников — в `ingest_runs`; нельзя сохранять секреты в логах. Частичный сбой `--once` возвращает код 1 и оставляет пригодные старые данные; демон дожидается следующего цикла. Истёкшие записи не возвращаются как актуальные. `last_success_at` не обновляется на ошибке, время попытки фиксируется отдельно в журнале.

## Что загружается

- 94 направления перечислены в `data/knowledge/europe-sync.json`. Координаты, страна и временная зона получаются от геокодера Open-Meteo при совпадении названия и кода страны. Неоднозначные/ненайденные объекты не подставляются. Для регионов используется явная точка: Фира для Санторини, Каламбака для Метеор, Санта-Крус для Тенерифе и Ньюки для Корнуолла. Это не покрытие региона целиком. Геокодирование кэшируется на 7 дней.
- Open-Meteo поставляет текущую температуру воздуха, осадки, глубину снега и прогноз средней температуры на текущий день (`avg_c`, прогноз, не климатическая норма). Снег в ответе API переводится из метров в сантиметры. Для выбранных побережий Open-Meteo Marine может возвращать температуру ближайшей морской ячейки; её координаты хранятся в записи и должны находиться не дальше 35 км от точки города. Это не измерение температуры на конкретном пляже. Прогноз и климатические среднемесячные значения из текущей температуры не вычисляются.
- Overpass ищет до 150 объектов в радиусе 3 км (для Швейцарии — региональный `overpass.osm.ch`, для остальных — `overpass-api.de`): реальные карточки отелей и POI с ссылкой на OSM и указанием ODbL. OSM-теги животных и звёзд сохраняются при наличии; они могут устаревать и не подтверждают наличие номера. Ограничение выборки означает, что количество найденных объектов не является полным количеством POI города. При трёх последовательных ошибках Overpass цикл временно прекращает вызовы источника и продолжает другие; следующий цикл попробует снова.
- Travelpayouts Data API даёт кэшированные авиаоценки MOW → аэропорт-кандидат в RUB. В БД сумма хранится в копейках, `price_basis=provider_cached_ticket`, `bookable=false`; авиакомпания и даты берутся только из ответа. Состав, пересадки и время полёта не выдумываются. Пустой ответ — отсутствие оценки, не отсутствие рейсов.
- Координаты указанных командой аэропортов берутся из публичного справочника Travelpayouts. OSRM рассчитывает маршрут **от этого аэропорта до точки города**: расстояние и длительность сохраняются в `routes`, цена неизвестна. Код не доказывает, что аэропорт является ближайшим. Расстояние не превращается в платную котировку трансфера и не подтверждает заселение в 14:00.
- В качестве исторической справки загружается [открытый датасет Passport Index](https://github.com/imorte/passport-index-data), собранный независимым автором с passportindex.org. На момент проверки датасет обновлён **17 февраля 2026 года**. Коммит фиксируется, дата и источник сохраняются в `passport_index_reference`, доступном через `GET /api/v1/visa/reference?passport=RU&destination=RS`. Это `historical_unverified`, не действующее визовое решение. В `visa_rules` статус остаётся `unknown`; официальные ссылки для отдельных стран доступны в `/api/v1/tools/entry-rules`.

Существующие mock-таблицы демо не удаляются: этот worker их не импортирует и не использует. Для поиска по фактически найденным POI агент вызывает `POST /api/v1/explore` с `{"month":11,"vibe":"culture","real_only":true}`; поддерживаются `beach`, `culture`, `ski`, `nature`, `spa`, результат содержит `vibe_match.osm_poi_count`. Это не подтверждает сезонность, а отсутствие POI не доказывает отсутствие объектов. Для исследования города агент вызывает `POST /api/v1/catalog/context`; для проверки отсутствия неподтверждённых поездок отправляет `POST /api/v1/tours/search` с `{"request": ..., "real_only": true}`. `search.data_mode=none`, пустые `options` и `booking=unavailable` означают, что пока нет полного набора проверенных предложений. Это не ошибка 500 и не подтверждение, что вариантов поездки не существует.

## Открытые ограничения

Цены Xotelo не сопоставляются автоматически с OSM и не считаются подтверждёнными котировками; плата за трансфер и датированные ЖД-предложения требуют партнёрского API. Нельзя заполнить таблицы `hotel_quotes`/`transfer_quotes` стоимостью из OSRM, угадать время заселения, продолжительность авиарейса, перевозчика или визовый срок. Полный реальный тур возможен только при наличии совместимых по датам/гостям/валюте, актуальных и проверяемых цен всех компонентов.

## Проверка 27 октября 2026

Первый полный проход завершился `partial`: 94 геокодированных точки, 94 наблюдения погоды, 30 морских ячеек, 94 маршрута и 83 авиаоценки. Основной Overpass для трёх первых городов завершился ошибкой и до следующего цикла был отключён circuit breaker. Отдельная загрузка швейцарского сервера и повтор Интерлакена дали 326 активных карточек размещения и 237 POI в четырёх точках, с ограничением выдачи 150 объектов на запрос. Отдельный проход `--weather-only` обновил суточный прогноз средней температуры для всех 94 направлений. Passport Index дал 25 исторических записей для паспорта РФ; они не заменяют `visa_rules=unknown`.

Значения и количество успешных ответов меняются. Истёкшие снимки и ошибки видны в журнале, а количество объектов в ограниченном радиусе не отражает полный каталог. Данные Overpass по остальным странам до успешного ответа остаются неполными; полные реальные туры без подтверждённых тарифов не создаются.

## Выгрузка для команды

```bash
uv run python scripts/export_database.py --real-only --output .runtime/europe-real-export.sqlite3
```

Выгрузка включает европейские направления, активные снимки OSM, неистёкшую погоду, маршруты и авиаоценки, а также исторический визовый справочник и записи `unknown`. Mock-отели и котировки, демобандлы, планы и заказы не переносятся. Файл можно читать SQLite-инструментами; источники быстро устаревают и требуют обновления в общей рабочей БД. Стандартный запуск приложения дополнительно инициализирует демокаталог, поэтому для строгого чтения без него используйте выгрузку напрямую или отдельный режим `real_only` в API; не считайте её весь срок актуальной.
