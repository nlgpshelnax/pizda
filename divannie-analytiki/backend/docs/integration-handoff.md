# Передача backend ролям 1 и 3

Сервис хранит каталог в SQLite, а чат и UI обращаются к HTTP API. Полные варианты и заказ сейчас **mock**. Публичная схема — `/docs` после запуска или [OpenAPI](openapi.json). [Запуск и сценарии защиты](demo-backend.md).

## Роль 1: агент

| Задача | Запрос | Что учитывать |
|---|---|---|
| Исследование города | `POST /api/v1/catalog/context` | Тело `{"city":"Сочи","start_date":"2026-11-10","end_date":"2026-11-15","origin":"MOW"}`. Только БД; `sections.*.status=missing` означает отсутствие подходящих данных; `warnings` обязательны для объяснения |
| Оценки отелей | `GET /api/v1/hotels/estimates?city=Дубай&check_in=2026-11-10&check_out=2026-11-15&adults=2` | Цена в копейках за комнату за ночь, одна комната, без детей; `bookable=false`, налоги неизвестны. Проверить даты, TTL, `last_sync` и предупреждения |
| Оценки ЖД | `GET /api/v1/rail/schedule?origin=Москва&destination=Казань` | Время московское, расписание без даты; `bookable=false`. `last_sync` и `warnings` сообщают о сбое. Не использовать для конкретной стыковки |
| Найти тур | `POST /api/v1/tours/search` | Тело `{"request": <TripRequest>}`; точный пример `request` — вложенный объект из `data/fixtures/search-request.json`. `search.options` содержит только прошедшие проверки варианты; причины — `search.rejected` |
| Создать план | `POST /api/v1/plans` | В тело передать сам `TripRequest`, без обёртки. Сохранить `id` и версию ответа |
| Изменить план | `PATCH /api/v1/plans/{id}` | `{"base_version":1,"changes":{"check_in":"2026-11-12","check_out":"2026-11-17","guests":{"children_ages":[7]}}}`. Взрослые и другие незаданные поля сохраняются. На `409 STALE_PLAN_VERSION` загрузить актуальный план и повторно сопоставить изменение |
| Выбрать вариант | `POST /api/v1/plans/{id}/selection` | `{"base_version":2,"bundle_id":"..."}`; использовать новую версию из ответа |

Запрос для поиска и сборки требует origin, destination, точные даты, число взрослых и возраст детей. Живые котировки не применяются автоматически к демобандлу. Цена бандла — RUB за всю поездку и всех гостей, а не цена за ночь. `visa.visa_status=unknown` и `requires_verification=true` — права на въезд не проверены; `source_url` — ссылка на официальный портал, а не результат проверки.

## Роль 3: интерфейс

- Для карточек используйте `search.options[].bundle`, `total`, `reasons`, `issues`; сумму показывайте из `total.amount`/`currency`.
- Показывайте `data_mode=mock`, `DEMO_DATA`, `limitations`, `visa` и предупреждения источников. `NO_MATCHING_DATA` и пустые `options` показывайте как отсутствие подходящих данных, а не как нулевую цену.
- `search.rejected` содержит коды и сообщения отбраковки; предупреждение `severity=warning` отличается от ошибки `severity=error`.
- Времена в бандле — ISO 8601 с часовым поясом. Проверки уже выполнены backend; время OSRM отдельно не является ценой трансфера.
- Состояния загрузки, ошибки и отсутствия предложений согласуйте с ролью 1. Повторные действия должны использовать актуальную версию плана; `pending` не является подтверждением услуги, `demo_only` — реальной покупкой.

Контракты чата и SSE/polling ещё должен реализовать владелец агента. Проверка этих HTTP-примеров не заменяет совместный прогон фактического агента и UI.
