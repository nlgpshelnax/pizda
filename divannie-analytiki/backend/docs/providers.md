# Источники, доступ и устойчивость

Актуальное состояние 0.3.0: [полная поставка Backend/Data](data-delivery.md). Более ранние ограничения ниже относятся к соответствующим этапам; текущие endpoints и блокеры перечислены в итоговом отчёте.
Названия на доске — ориентиры интеграций, не доказательство наличия публичного endpoint. Ни один live-адаптер в этом каркасе не реализован и не проверен. Async provider runner, HTTP-нормализация и SQLite TTL-кэш уже реализованы; [проверенный объём](data-milestone-1.md). Не подключаем неизвестные библиотеки с похожими названиями вместо проверки официального API.

| Данные с доски | Планируемый источник | Что проверить до разработки |
|---|---|---|
| Place / planes / guests | Travelpayouts API либо согласованный MCP | конкретный продукт, schema, credentials, права, affiliate marker, покрытие; поисковые/кэшированные цены не равны bookable offer |
| Hotels / stars / budget | Travelpayouts + «Viajante» с доски | точное название/URL второго поставщика и условия доступа; источник отельных тарифов, состав цены, дети, животные, питание, availability |
| Weather | Open-Meteo | `api.open-meteo.com`, forecast horizon, timezone, rate limits, лицензия; для дальних дат нужна климатология с отдельной меткой |
| Car | OSRM | согласованный HTTP endpoint либо свой сервер; координаты lon,lat, duration/distance; **нет тарифа такси, вместимости или гарантии трансфера** |
| Vibe | OSM Overpass + база знаний роли 5 | политика выбранного Overpass instance, tags, геокодирование, лимиты; наличие POI не доказывает тишину/безопасность |
| Visa | Passport Index / подтверждённые официальные источники | лицензия, дата актуальности, гражданство, тип паспорта, цель, срок, транзит; страна проживания не равна гражданству |
| Train (только РФ) | «rzd-api» с доски | официальный/партнёрский источник, право доступа, тарифы, расписание, возврат; не считать неофициальный пакет API РЖД |
| Transfers | отдельный партнёр или явный mock | цена, вместимость, детское кресло, животные, время ожидания, ночные доплаты |

Для раннего MVP выберите один доступный транспортный источник и один отельный; остальные используют **явный** mock, пока нет доступа. Не блокируйте общий контракт ключами. Ключи вводятся через настройки окружения, никогда через Git или чат. `.env.example` не содержит ключей; текущий сервис их не запрашивает.

## Travelpayouts как основной кандидат

Ссылка команды: https://app.travelpayouts.com/all_tools — раздел инструментов партнёрского кабинета, а не базовый URL единого API. Содержимое авторизованного кабинета в этой среде не проверено. Для подключения роль 2 должна открыть доступную аккаунту документацию конкретного продукта и зафиксировать endpoint, auth, разрешённые операции, лимиты и состав ответа.

План: Travelpayouts — основной кандидат для авиаданных; возможность получения отельных предложений проверяется отдельно. Доступ к API данных/статистики не означает доступ к live search, подтверждению наличия или бронированию. Если доступны только кэшированные/минимальные цены, используйте их как исследовательские оценки с датой и provenance, не как подтверждённый тариф для всей поездки. API не обязательно поставляет политику детей, животных или раннего заезда — эти поля нельзя выдумывать.

Отдельно остаются Open-Meteo (погода), OSRM (маршрут/длительность), источники правил въезда, ЖД и тарифов трансферов. «Travelpayouts MCP» на доске не доказывает, что команде выдан готовый MCP-сервер: если выбран MCP, нужны адрес сервера, перечень tools и проверка доступа; если REST — официальный контракт конкретного продукта. Ключи добавляются через настройки среды, а не в Git/чат.

## Контракт адаптера (следующий этап)

`search(normalized_request) -> ProviderResult[Quote]`, где результат содержит status (`ok`, `empty`, `timeout`, `unauthorized`, `unavailable`, `rate_limited`), котировки, источник, задержку и warnings. Нормализованные котировки валидируются Pydantic. `empty` не равно ошибке сети; неизвестные условия остаются `null`, а не превращаются в `false`/`true`.

Реализовано: HTTP connect timeout 3 секунды, timeout запроса 5 секунд, deadline runner 10 секунд, не более одного retry при unavailable, concurrency до 4 на runner. 400/401/403/429 не ретраятся автоматически. Retry-After и circuit breaker ещё не реализованы. Deadline включает очередь semaphore и вызовы provider, но не локальные операции SQLite. Это настройки, не измеренные SLA; проверять на реальном демо-оборудовании.

## Кэш и mock-слой

Ключ: provider + schema version + operation + нормализованный JSON **всех** параметров, влияющих на ответ (даты, место, гости/возрасты, животные, валюта, тариф и фильтры). Нельзя кэшировать только по городу. Срок жизни задаётся контрактом провайдера; стартовая политика для исследования: цены 15 минут, погода 1 час, маршруты 24 часа. Нельзя сохранять дольше, чем разрешает поставщик.

Планируемая цепочка: live → свежий cache → явно помеченный устаревший snapshot для исследования. Истёкшее предложение нельзя подтверждать как доступное к покупке. Синтетический fixture — отдельный режим всего демо; **не подмешивать его молча в live-ответ**. При отсутствии данных возвращать ошибку/ограничение и продолжать независимые компоненты. Политика будущего snapshot-режима отличается от текущего валидатора: сейчас истёкшая не-mock котировка блокирует бандл.

Текущий `MockCatalog` — источник fixtures, он читает JSON на старте и работает без сети. Поверх `MockBundleProvider` работает SQLite TTL-кэш; область цены повторно проверяется валидатором. Политика не допускает подмешивания mock в live или использования expired quote. Полного режима snapshots/live пока нет. API не обещает резервирование, реальную доступность или стоимость.

## Метрики и чувствительные данные

Логировать request_id, provider, operation, latency_ms, status, cache_hit, fallback_kind, число отсеянных котировок и код причины. Для жюри: p50/p95 поиска, доля успешных ответов поставщика, доля fallback, количество выявленных ошибок времени. Число уточнений собирает AI-слой. Не логировать токены, паспортные данные, полные сообщения и credential-bearing URL. В текущем ответе provider_reports содержит status, attempts, latency_ms и cache_hit; постоянные logs и агрегаты p50/p95 ещё не реализованы.

Выбор первого API и конкретные шаги для кабинета: [подключение Travelpayouts](travelpayouts-setup.md). Официальная документация Data API найдена; доступ аккаунта и API-вызов ещё не проверены.
