## Как получить реальный доступ

Для Суточно.ру Travelpayouts просит обратиться в поддержку и указать URL проекта, описание, ежемесячное число посетителей, телефон и ФИО владельца, необходимые данные. Не нужно выдумывать посещаемость: указать, что это хакатонный прототип. После одобрения нужна документация именно выданного API и безопасный секрет среды. До этого нельзя заявлять, что тарифы доступны.

Для Transferz: на [официальной странице](https://www.transferz.com/solutions/api) выбрать **Request API Access** и запросить sandbox. Уточнить условия, наличие оплаты и покрытие Сочи/Казани/Дубая/Хургады; sandbox не означает реальное бронирование. Выданный ключ не присылать в чат. При подключении сначала реализовать read-only поиск: route, pickup time, пассажиры, багаж, детские кресла, животные, валюта, fees, время действия и происхождение. Бронирование требует отдельного согласования.

## ЖД: использование и проверка

```bash
uv run python scripts/sync_tutu.py
# работающий сервер:
curl --get http://127.0.0.1:8000/api/v1/rail/schedule \
  --data-urlencode 'origin=Москва' --data-urlencode 'destination=Казань'
```

Обновление также выполняется online worker `scripts/sync_service.py` или `scripts/ingestion_worker.py` по его интервалу; API читает SQLite без сети. Срок жизни снимка — шесть часов, время в ответе — московское, дата отправления не предусмотрена источником. При ошибке старый снимок сохраняется до истечения срока. Обе цены и расписание нельзя использовать для финального расчёта тура или стыковки; это может сделать только отдельный источник предложений на конкретный день/состав пассажиров. Индивидуальные права API и условия использования уточняются у Travelpayouts/Tutu.

## Что остаётся сделать после доступа

1. Реализовать клиент и контрактный тест на **официально выданной** схеме партнёра, затем проверить реальный read-only ответ.
2. Записать предложение с точными датами и гостями, валютой, составом цены, датой получения/истечения и ссылкой на исходный товар. Не сопоставлять разные каталоги по одному лишь названию.
3. Подключить к сборщику только совместимые предложения; перед подтверждением повторно проверить цену, наличие, правила и время. Не смешивать mock с real в одной поездке.
4. Совместно с владельцами агента и UI прогнать сценарий и падение источника. До готовности этих условий полный тур остаётся mock.
