# О!дин запрос — путешествия с локальной Qwen

React-интерфейс → HTTP API Python-агента → локальная Ollama/Qwen → ответ в чате. Туристические варианты берутся из включённой SQLite `travel.db`. API-ключи и платные внешние сервисы для запуска не нужны.

## Быстрый старт на macOS / Linux

Установите:

- [Python](https://www.python.org/downloads/) 3.10+ (рекомендуется 3.12).
- [Node.js](https://nodejs.org/) 24 LTS, включая npm.
- [Ollama](https://ollama.com/download).

Затем выполните в терминале:

```bash
git clone https://github.com/nlgpshelnax/pizda.git
cd pizda
bash start.sh
```

Скрипт создаст Python-окружение, установит зависимости, запустит Ollama при необходимости, скачает `qwen2.5:7b-instruct`, если модели ещё нет, и запустит агента и UI. При первом запуске нужен интернет и несколько ГБ места для модели. Qwen работает локально; скорость зависит от памяти и процессора/GPU. Первый запрос после загрузки модели может быть дольше.

Когда появится `ГОТОВО`, откройте **http://localhost:8080**. Напишите:

> Хочу в Сочи из Москвы в ноябре, бюджет 100 тысяч рублей

Оставьте терминал открытым. **Ctrl+C** останавливает процессы, которые запустил скрипт. Уже работающую Ollama он не останавливает. Для повторного запуска достаточно `bash start.sh`. Для предварительной установки зависимостей есть `bash setup.sh`.

Если порты 8000 или 8080 уже заняты, скрипт сообщит об этом и завершится. Найти старый процесс:

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
lsof -nP -iTCP:8080 -sTCP:LISTEN
```

Остановите свой старый сервер в его терминале через Ctrl+C. Скрипт сам чужие процессы не завершает.

## Что входит

| Путь | Назначение |
| --- | --- |
| `front/frontend` | React/Vite UI, стили, изображения, тесты |
| `divannie-analytiki/agent_api.py` | HTTP API, порт 8000 |
| `divannie-analytiki/core` | Агент, извлечение параметров, workflow и поиск |
| `divannie-analytiki/travel.db` | Готовый учебный каталог SQLite |
| `divannie-analytiki/prompts` | Промпты Qwen, включая короткий HTTP-промпт |
| `divannie-analytiki/backend` | Дополнительный Data API, исходники и документация; для быстрого старта не требуется |
| `scripts/dev.py` | Установка, запуск и проверки |

В репозитории находятся обычные файлы обоих проектов; submodule и отдельные clone не требуются. Виртуальное окружение, node_modules, секреты, старые Git-истории и результаты сборки не включены. Исходные README в подпапках описывают также прежние и дополнительные сценарии; для текущего запуска используйте эту инструкцию.

## Проверки

После установки зависимостей:

```bash
python3 scripts/dev.py check
```

Проверяет целостность и содержимое настоящей БД, поиск и суммы пакетов, HTTP health, CORS, валидацию, TypeScript, production-сборку и unit-тесты UI. Эти проверки не подтверждают генерацию модели.

Полный браузерный путь с настоящей моделью проверяется **при работающем `bash start.sh`** в другом терминале:

```bash
cd front/frontend
node node_modules/playwright/cli.js install chromium
node scripts/agent-e2e.mjs
```

Успех: две строки `PASS: UI → Agent HTTP API → Qwen → UI`. Скрипт проверяет наличие нужной модели, отправляет два сообщения через UI и сравнивает текст с HTTP-ответом. Моки и перехват ответов не используются.

## Адреса и настройка

- UI: **http://localhost:8080**.
- Health API: **http://localhost:8000/api/health** — проверяет БД, а не доступность модели.
- Документация HTTP API: **http://localhost:8000/docs**. На `/` API возвращает 404 — это нормально.
- Ollama OpenAI-compatible API: **http://localhost:11434/v1**.
- Модель: **qwen2.5:7b-instruct**.
- CORS: `http://localhost:8080`, `http://127.0.0.1:8080`.

Для ручного запуска и изменения адресов:

```bash
# Терминал 1 (если Ollama ещё не запущена)
ollama serve

# Терминал 2, из корня репозитория
ollama pull qwen2.5:7b-instruct
cd divannie-analytiki
OLLAMA_HOST=http://localhost:11434/v1 OLLAMA_MODEL=qwen2.5:7b-instruct \
  .venv/bin/python -m uvicorn agent_api:app --host 127.0.0.1 --port 8000

# Терминал 3, из корня репозитория
cd front/frontend
VITE_AGENT_API_URL=http://localhost:8000 \
  node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 8080
```

Ручные команды предполагают, что зависимости уже установлены через `bash setup.sh`. Дополнительные переменные агента: `AGENT_DATABASE_PATH` (абсолютный путь к SQLite), `AGENT_CORS_ORIGINS` (origin через запятую). Переменные передаются через окружение; HTTP-путь не загружает `.env` с секретами. Быстрый запуск использует указанные выше локальные адреса.

## Скорость и ограничения

HTTP-путь использует два вызова Qwen: извлечение параметров (до 768 выходных токенов) и короткий ответ (до 256). Промпт извлечения сокращён с 34 КБ до 1,7 КБ; на финальный ответ передаются краткие результаты поиска. В логе API есть `Agent timings` с временем этапов, без текста сообщений. При ошибке модели API возвращает 502, UI показывает ошибку вместо выдуманного ответа.

SQLite содержит 1000 отелей, 2220 транспортных записей и 576 погодных записей. Это учебный каталог, цены не являются актуальными предложениями. Оформление поездки и напоминания в UI демонстрационные: оплаты, настоящих броней и внешних уведомлений нет. Сессия чата сохраняется в браузере; для чистой проверки сбросьте старый чат.

Проверено при подготовке: офлайн-проверки БД/API, production-сборка и 107 unit-тестов UI. Полный live-e2e на Qwen в среде подготовки ограничен запретом локальных сокетов; команда выше предназначена для проверки на вашем компьютере.
