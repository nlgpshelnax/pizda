# О!дин запрос

Работающий локальный прототип конструктора путешествий для хакатона Островка. React + TypeScript + Vite. Данные, цены, отели, расписания и бронирование демонстрационные; приложение не вызывает LLM, API бронирования или настоящую базу данных.

## Запуск в VS Code

1. Откройте в VS Code папку `Хакатон`.
2. Откройте **Терминал → Новый терминал**.
3. Выполните:

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Откройте **http://localhost:8080**. На Windows используются команды `npm.cmd`, чтобы запуск не зависел от политики PowerShell для скриптов. На macOS/Linux можно использовать обычный `npm`.

Нужен Node.js 24.13+ или 26. Проверено на Node.js 26.8.2. Чтобы остановить сайт, нажмите Ctrl+C в его терминале. Порт 8080 должен быть свободен.

## Запуск через Docker

Из корневой папки проекта:

```powershell
docker compose up --build
```

Сайт: **http://localhost:8080**. Проверка работоспособности: **http://localhost:8080/health**. Остановка: `docker compose down`.

Подготовлены `docker-compose.yml`, многоэтапный `frontend/Dockerfile` и конфигурация nginx. На машине разработки Docker отсутствовал, поэтому фактическая контейнерная сборка не проверялась. Dev-сервер, production-сборка и `/health` проверены напрямую. Для общего compose команды можно перенести сервис `frontend`, сохранив отдельный build context и согласовав порт.

## Что работает

- Приветственный экран, свободный запрос и примеры для вдохновения.
- На десктопе диалог слева (40%), предложения справа (60%). На телефоне переключатель «Чат / Поездки». Панели имеют независимую прокрутку в пределах окна; поле ввода чата остаётся доступным.
- Enter отправляет сообщение, Shift+Enter добавляет строку. Есть состояние обработки.
- Четыре параметра со статусами `YES / Vague / NO`, их редактирование и сохранение между сообщениями.
- Blocker: любые 3–4 полезных параметра допускают подбор; из двух допускается **только `when + origin`**. «Куда-нибудь» и «хочу отдохнуть» не считаются полезными параметрами.
- 15 вымышленных поездок: Испания, Италия, Португалия, Франция, Сербия, Черногория, Венгрия, Австрия, Греция.
- До 5 подходящих вариантов: две основные поездки и до трёх компактных альтернатив. На 1440×900 все пять предложений видны на одном экране. На средних экранах основные карточки становятся вертикальными. Полный маршрут, отель и расходы открываются по действию «Подробнее» до оформления. Доступны сравнение, сортировка по цене и избранное.
- Отель, иллюстративное фото направления, перелёт, трансфер, занятия, полный маршрут, стоимость и объяснение подбора.
- Отдельные пояснения «Почему подходит», «Компромисс», «Что проверить» и визовый статус в предложении.
- Предположения о датах, гостях и ночах явно обозначены. Месяц не выдаётся за выбранную точную дату.
- Сезонные противоречия, бюджет против звёздности, виза и гражданство, питомцы, проверка времени регистрации и запаса до обратного рейса.
- Жёсткие ограничения не ослабляются автоматически. Предлагаемые компромиссы требуют выбора пользователя.
- Пересборка с сохранением контекста: питомец, бюджет, даты, отель, направление, гражданство, трансфер.
- Демо-оформление требует точной даты, корректных гостей и города. При корректном изменении полей цена и маршрут пересчитываются автоматически, без обращения к агенту и без отдельной кнопки пересчёта. Есть одна финальная кнопка «Оформить демо-поездку». Нет оплаты и настоящей резервации.
- После оформления: запрос раннего заезда, изменение трансфера, перенос дат и скачивание одностраничного PDF-плана. Изменение дат снимает статус оформленного демо-плана, скрывает скачивание PDF и приостанавливает напоминания до повторного оформления. Доступна явная отмена демо-бронирования.
- В оформлении есть календарь с русскими названиями месяцев, выбором с клавиатуры и ручным вводом даты. Примеры на главной передают только видимые пожелания, без скрытого города, даты или бюджета.
- Диалог, выбранный план, отдельный снимок демо-бронирования и настройки напоминаний сохраняются в `localStorage` этого браузера, включая закрытие и повторное открытие приложения. «Новая поездка» с подтверждением сбрасывает сессию и отключает напоминания. Избранное является временным состоянием интерфейса.
- Шрифты Prata и Montserrat, фотографии находятся в `public/`; при обычном использовании загрузка внешних ресурсов не нужна. Century Gothic используется только как системный fallback.

## Напоминания после демо-оформления

В «Моей поездке» включите компактный блок «Напомнить о поездке». Можно выбрать несколько сроков: за 7 дней, за 1 день и за 3 часа **до точного времени отправления**. Сохранённые времена и ближайшее напоминание показаны в интерфейсе. Прошедшие времена недоступны для нового планирования.

Данные остаются в браузере; **push, SMS и письма не отправляются**. При закрытом сайте уведомлений нет. Для внешних напоминаний скачайте `.ics` и импортируйте его в свой календарь. Он содержит начало пути, возвращение домой, направление и выбранные будущие `VALARM`. Время хранится в UTC, отображение учитывает пояс города отправления.

После переноса или отмены настройки на сайте отключаются, выбранные интервалы сохраняются для повторного включения. Скачанный календарный файл сам не обновляется: после переноса экспортируйте актуальный файл, после отмены удалите старое событие вручную.

Неизвестному городу не подставляется московский часовой пояс: перед оформлением и экспортом нужно уточнить поддерживаемый маршрут.

Текущая переработка интерфейса: [FRONTEND-REBUILD.md](frontend/docs/FRONTEND-REBUILD.md). Предыдущие изменения логики и напоминаний: [UX-REDESIGN.md](frontend/docs/UX-REDESIGN.md).

## Запросы для демонстрации

Начните новую поездку для независимых сценариев.

| Сценарий | Запрос | Ожидаемое поведение |
|---|---|---|
| Обычный подбор | `В июне из Москвы в Италию, хочу архитектуру` | Сразу предлагает варианты в Италии |
| Два разрешённых параметра | `В декабре из Москвы` | Сразу предлагает до пяти поездок |
| Два других параметра | `В декабре в Италию` | Задаёт вопрос о городе отправления |
| Три параметра без даты | `Из Питера в Испанию, хочу посмотреть архитектуру` | Подбор начинается, даты помечены как примерные |
| Недостаточно данных | `Хочу в Париж` | Сохраняет направление и задаёт один вопрос |
| Зимнее море | `В декабре из Москвы в Европу, хочу купаться в тёплом море` | Показывает конфликт и варианты с пометкой о компромиссе |
| Жёсткое море | `В декабре из Москвы в Европу, только море, бассейн не подходит` | Не подменяет море бассейном, просит изменить условие |
| Дорогой отель | `В декабре из Москвы в Европу, только 5 звёзд, до 90 тысяч` | Объясняет конфликт, предлагает согласованные изменения |
| Питомец | После подбора: `Теперь с нами едет собака` | Исключает отели без животных, учитывает дополнительные расходы |
| Снижение бюджета | `Хочу подешевле` | Снижает текущий бюджет или стоимость выбранной поездки на 20% и пересчитывает |
| Без визы | `Хочу без визы`, затем `У меня паспорт РФ` | Сначала уточняет паспорт, затем включает учебный визовый фильтр |
| Точные детали | `12 декабря, 1 взрослый, 6 ночей` | Фиксирует дату, гостей и длительность |
| Перенос | После точной даты: `На два дня позже` | Сдвигает начало и конец, сохраняя ночи и остальные параметры |
| Новый отель | `Сделай вместо пяти звёзд четыре` | Обновляет категорию |
| Неизвестный запрос | `абракадабра` | Честно сообщает об ограничениях и сохраняет параметры |

Если запрос «подешевле» делает бюджет меньше самого дешёвого подходящего варианта, приложение показывает отсутствие результатов. Это ожидаемое поведение: неподходящие предложения не добавляются ради количества.

## Проверки

Из папки `frontend`:

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run dev
```

В другом терминале, пока сайт запущен:

```powershell
cd frontend
npm.cmd run test:e2e
npm.cmd run test:redesign
npm.cmd run test:visual
```

Браузерные сценарии используют установленный Microsoft Edge в Windows. На других системах используется Chromium из Playwright (при необходимости установите его командой `npx playwright install chromium`). Чтобы выбрать другой установленный канал, задайте `BROWSER_CHANNEL`; чтобы проверить другой адрес, задайте `BASE_URL` для E2E.

- Unit-тесты: все 16 комбинаций блокеров, синонимы, контекст, даты и оценки, жёсткие ограничения, конфликты, сумма расходов, расписание и изменения состояния.
- E2E: ввод, уточнения, полный маршрут, финансы, сравнение, переключение, избранное, скачивание, конфликты, пересборка, оформление и действия после него, редактор, восстановление вкладки и мобильные размеры.
- Проверено после переработки: 102 unit-теста (в том числе все 16 комбинаций Blocker), 11 основных и 12 дополнительных браузерных сценариев, TypeScript и production build.
- Визуальные снимки и машинные отчёты создаются в `frontend/test-results/` (не включаются в Git).

## Подключение настоящего агента

Внутренний интерфейс `AgentAdapter` отделён от компонентов. По умолчанию используется `MockAgentAdapter`; стабильный экземпляр другого `AgentAdapter` можно передать через `<App agentAdapter={...} />`. Это заменяет только обработку чата: оформление, перерасчёт и расписания пока используют локальные демо-правила и требуют отдельной интеграции.

Это **предварительный внутренний формат**, а не согласованный контракт бэкенда. Подробности и список необходимых решений команды находятся в [frontend/docs/INTEGRATION.md](frontend/docs/INTEGRATION.md).

## Ограничения и исходные материалы

- Это детерминированная имитация по правилам, а не настоящая LLM. Поддерживается ограниченный словарь русских формулировок, 6 городов отправления и направления каталога. Неизвестные города и цели сохраняются отдельно от поддержки каталога. При неоднозначной роли города агент уточняет её. Предложения по произвольным странам, детские тарифы, сложные отрицания и многогородские маршруты не поддерживаются.
- Предположение о 6 ночах, 1 взрослом, завтраках и экономе является учебным. Номера, рейтинги, тарифы, багаж и условия отмены не являются реальными предложениями. Ранняя регистрация фиксируется только как запрос.
- Базовые цены заданы за 6 ночей; стоимость масштабируется по ночам, гостям, условному коэффициенту города отправления, питомцу и трансферу. Номер учитывается на каждых двух взрослых. Никакой реальной доступности нет.
- Учебный визовый справочник поддерживает только паспорт РФ и не обновляется в реальном времени. Для другого или неизвестного гражданства показывается «Нужно уточнить». Нельзя использовать эти данные как актуальную визовую консультацию.
- Для воспроизводимости демо опорная дата: **25 октября 2026 года**. Месяцы до октября без указанного года относятся к 2027 году, октябрь–декабрь к 2026. Для реального продукта дату нужно получать от бэкенда и учитывать часовой пояс пользователя. Сезон представлен ориентировочным месяцем.
- Цены, времена рейсов и маршруты учебные. Без точной даты и города отправления расписание не показывается как определённое. Для точных дат местное время пересчитывается через IANA-зоны, длительность включает двухчасовую пересадку; отдельно показаны получение багажа и запас до обратного рейса. Для реальных перелётов нужен источник расписаний и повторная проверка маршрута.
- Изменения сохраняются в локальном хранилище браузера; авторизация, синхронизация между устройствами и серверное хранение не реализованы.
- Перед созданием изучен полный приложенный текст запроса и предоставленные изображения. Рабочая папка была пуста. `Скелет_проекта.pdf`, `interface.md`, `кейс.md` и `правила.md` не найдены в рабочей папке, ближайших документах и вложениях. Архитектура реализована по подробному заданию; сверить её с отсутствующими документами пока невозможно. Код других участников не изменялся.
